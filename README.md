# Колонк — ШТС POS & Cloud ERP

Шатахуун түгээх станцын бүрэн систем: touch-first POS, ээлжийн менежмент, савны хяналт,
худалдан авалт, B2B гэрээт борлуулалт, давхар бичилтийн нягтлан бодох бүртгэл, тайлан,
И-баримт (Ebarimt 3.0) дараалал, нөөшлөлт.

## Стек

| Давхарга | Технологи |
|---|---|
| Backend | FastAPI · SQLAlchemy 2.0 (async, asyncpg) · Pydantic v2 · Alembic |
| Өгөгдлийн сан | PostgreSQL 16 |
| Дараалал / кэш | Redis 7 + ARQ worker |
| Frontend | React 18 · TypeScript · Vite · Tailwind CSS v4 · Zustand · TanStack Query |
| Prod proxy | Nginx |

## Хурдан эхлүүлэх

### Хамгийн хялбар — 2 удаа дарах

| Файл | Үйлдэл |
|---|---|
| **`startup.bat`** | Локал dev: бүх системийг асааж, браузерыг автоматаар нээнэ |
| **`stop.bat`** | Локал dev-ийг зогсооно |

Docker-оор (шинэ PC, production) ажиллуулах бол `start-docker.bat` —
доорх [Docker горим](#docker-горим) ба [Шинэ PC дээр суулгах](#шинэ-pc-дээр-суулгах-production)
хэсгийг үз.

`startup.bat` нь дараах бүхнийг хийнэ (цэвэр төлөвөөс ~15 секунд):

1. dev өгөгдлийн санг асаах (тусдаа instance, порт 5434 — таны үндсэн
   PostgreSQL-д хүрэхгүй)
2. Redis (Memurai) шалгах
3. миграц + seed дата (идемпотент — дахин ажиллуулахад аюулгүй)
4. API (8000), ARQ worker, frontend (5173) асаах
5. бүгд бэлэн болтол хүлээгээд браузер нээх

Процессууд далд ажиллана, лог нь `logs\` хавтсанд бичигдэнэ
(`api.err`, `worker.err`, `frontend.err`).

### PowerShell-ээс нарийн тохируулгатай

```powershell
.\start-dev.ps1 -Seed      # seed дататай асаах
.\start-dev.ps1 -Open      # бэлэн болмогц браузер нээх
.\start-dev.ps1 -Quiet     # далд горим, лог файлд
.\start-dev.ps1 -Stop      # зогсоох
```

> Шинэ PC дээр `.ps1`-г шууд ажиллуулбал PowerShell-ийн анхдагч бодлого
> хориглодог (*"running scripts is disabled on this system"*). Хөгжүүлэгчийн
> машинд нэг удаа `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` гэж
> нээнэ, эсвэл `.bat` wrapper-уудыг ашиглана.

- POS: http://localhost:5173
- API баримт: http://localhost:8000/api/docs

Шаардлага: PostgreSQL 17 (`C:\Program Files\PostgreSQL\17`), Redis эсвэл
Memurai 6379 порт дээр, Python 3.12, Node 20+.

## Docker горим

Бүх зүйлийг нэг команд хийнэ (cmd, PowerShell аль ч терминалаас):

```bash
.\start-docker.bat -Prod
```

| Команд | Үйлдэл |
|---|---|
| `.\start-docker.bat` | dev горим — API :8000, frontend-ийг host дээр `npm run dev` |
| `.\start-docker.bat -Prod` | prod горим — бүгд Nginx-ээр **http://localhost** |
| `.\start-docker.bat -Down` | зогсоох |
| `.\start-docker.bat -Reset` | өгөгдлийн сангийн volume устгаж цэвэр эхлэх |

Скрипт дараах бүхнийг өөрөө хийнэ: VT-x ба Docker Desktop шалгах (байхгүй бол
юу хийхийг зааж өгнө) → `.env`-ыг санамсаргүй нууцтай үүсгэх → Docker Desktop
асаах → build → миграц → сан хоосон бол seed.

> **Яагаад `.bat` вэ?** Шинэ Windows PC дээр PowerShell-ийн анхдагч бодлого
> (`ExecutionPolicy=Restricted`) `.ps1` файлыг шууд ажиллуулахыг хориглодог —
> `.\start-docker.ps1` гэвэл *"running scripts is disabled on this system"*
> алдаа гарна. `.bat` wrapper үүнийг тойрч өгдөг. PowerShell-ээс шууд бол:
> `powershell -ExecutionPolicy Bypass -File .\start-docker.ps1 -Prod`

Гараар compose ашиглах бол:

```bash
docker compose --profile dev up -d
docker compose exec api python -m app.seed
```

Prod (Nginx-ээр http://localhost):

```bash
docker compose --profile prod up -d --build
```

> **BIOS дээр VT-x унтраалттай бол** скрипт *"BIOS дээр виртуалчлал (Intel
> VT-x) унтраалттай байна"* гэж зогсоно — Docker Desktop Linux контейнер
> ажиллуулахад VT-x зайлшгүй, үүнгүйгээр WSL2 ч ажиллахгүй. Гараар шалгах:
> `systeminfo` → Hyper-V Requirements → `Virtualization Enabled In Firmware: No`
> бол унтраалттай.
>
> **ASUS ROG STRIX B360-I GAMING дээр асаах алхам:**
> 1. Компьютерийг дахин асаах үед `Delete` товчийг дарж BIOS-д орно.
> 2. `F7` дарж **Advanced Mode** руу шилжинэ.
> 3. **Advanced** → **CPU Configuration**.
> 4. **Intel (VMX) Virtualization Technology** → **Enabled**.
> 5. `F10` → хадгалж гарна.
>
> Бусад үйлдвэрлэгчийн BIOS-д мөн "Virtualization Technology", "VT-x", "SVM
> Mode" (AMD) нэртэй тохиргоог **Enabled** болгоно. Дараа нь Docker Desktop
> асаахад `docker-desktop` WSL дистро автоматаар бүртгэгдэнэ.
>
> VT-x асаах боломжгүй бол **локал горим** (`startup.bat`) бүрэн ажиллах тул
> түүнийг ашиглана уу — функцын хувьд ялгаагүй.

## Шинэ PC дээр суулгах (production)

Дурын Windows компьютер дээр системийг бүрэн ажиллагаатай босгох алхмууд:

1. **Git** суулгана (байхгүй бол): <https://git-scm.com/download/win>
2. **WSL2** суулгана — Docker-ын ажилладаг VM давхарга. Үүнгүйгээр Docker
   Desktop *«Virtualization support not detected»* гэж гацдаг. PowerShell-ийг
   **Run as Administrator**-оор нээж:

   ```powershell
   wsl --install --no-distribution
   ```

   Дуусмагц компьютерээ **restart** хийнэ. (Store хаалттай орчинд:
   `wsl --install --no-distribution --web-download`.)
3. **Docker Desktop** суулгана: <https://www.docker.com/products/docker-desktop/>
   - BIOS дээр VT-x идэвхтэй байх ёстой — дээрх зааврыг үз.
   - Суулгасны дараа Docker Desktop-ыг **нэг удаа гараар нээж**, эхний
     тохиргоог дуустал хүлээнэ: Accept дарах, WSL2 шинэчлэлт асуувал
     зөвшөөрөх, зүүн доод буланд **Engine running** гарах хүртэл.
   - Нээлттэй байсан терминалаа хааж **шинээр нээнэ** (`docker` команд
     PATH-д шинэ терминалд л орж ирнэ).
4. Репог татна (private тул GitHub нэвтрэлт шаардана):

   ```powershell
   git clone https://github.com/ez4puljin/kolonk
   cd kolonk
   ```

5. Асаана — **`.bat` файлыг ажиллуулна** (`.ps1`-г биш, учир нь шинэ PC-ийн
   PowerShell бодлого `.ps1`-г шууд ажиллуулахыг хориглодог):

   ```powershell
   .\start-docker.bat -Prod
   ```

   Скрипт бүгдийг өөрөө хийнэ: VT-x, Docker Desktop шалгах → `.env`-ыг
   санамсаргүй нууцтай үүсгэх → Docker Desktop асаах → build → бүх сервис
   асаах → миграц → сан хоосон бол seed. Дуусахад **http://localhost** дээр
   систем бэлэн байна (демо хэрэглэгчид, ПИН `000000`). Ямар нэг зүйл дутуу
   бол скрипт улаанаар юу хийхийг зааж өгнө.

6. **(Сонголт) Хуучин компьютерээс өгөгдлөө зөөх бол:**

   ```powershell
   # Хуучин PC дээр — зөөвөрлөх багц үүсгэнэ:
   .\backup-data.bat
   ```

   Скрипт эх сангаа өөрөө олно: Docker db ажиллаж байвал түүнээс, үгүй бол
   локал хөгжүүлэлтийн сангаас (5434). Docker ажиллаж байхад локал сангаас
   авахыг хүсвэл `.\backup-data.bat -Local`.

   Гарсан `kolonk.dump` (+ `kolonk-uploads.zip` байвал) файлуудыг USB/cloud-оор
   шинэ PC-ийн repo хавтсанд хуулаад:

   ```powershell
   # Шинэ PC дээр — сан бүрэн дарагдаж, хуучин өгөгдөл орно:
   .\restore-data.bat
   ```

7. Өдөр тутмын удирдлага:

   ```powershell
   .\start-docker.bat -Down    # зогсоох
   .\start-docker.bat -Prod    # дахин асаах (өгөгдөл хадгалагдана)
   ```

   Тог тасрах/reboot-ын дараа Docker Desktop асмагц контейнерууд өөрсдөө
   сэргэнэ (`restart: unless-stopped`). Өгөгдөл `pgdata`, зургууд `uploads`,
   backup-ууд `backups` volume-д тус тус хадгалагдана.

## Ubuntu дээр суулгах (санал болгож буй сервер)

Станцын байнгын машинд Ubuntu тохиромжтой: Docker виртуал машингүй шууд
ажилладаг тул Windows дээрхээс хөнгөн, хурдан бөгөөд цахилгаан тасарсны
дараа өөрөө сэргэдэг. **i3 + 8GB RAM илүүдэлтэй** — стек нийтдээ ~2GB иднэ.

### 1. Docker суулгах

Docker **Desktop биш, Engine** суулгана (Desktop нь Линукс дээр илүүц
виртуал машин үүсгэдэг). Ubuntu-гийн агуулахын `docker.io` биш, Docker-ын
албан ёсны агуулахаас авбал compose plugin хамт ирнэ:

```bash
curl -fsSL https://get.docker.com | sudo sh
```

Дараа нь өөрийгөө `docker` бүлэгт нэмнэ (эс бөгөөс команд бүрд `sudo`
бичих болно):

```bash
sudo usermod -aG docker $USER
```

**Нэг удаа гарч, дахин нэвтэрнэ** (эсвэл машиныг унтрааж асаана) — бүлгийн
эрх тэгж идэвхжинэ. Шалгах:

```bash
docker run --rm hello-world
```

### 2. Кодоо татаж, тохируулах

```bash
sudo apt install -y git
git clone https://github.com/ez4puljin/kolonk.git ~/kolonk
cd ~/kolonk
cp .env.example .env
```

`.env`-ээ засна (`nano .env`). Заавал бөглөх:

| Түлхүүр | Утга |
|---|---|
| `POSTGRES_PASSWORD` | хүчтэй нууц үг |
| `DATABASE_URL` | дээрх нууц үгийг мөн энд бичнэ |
| `JWT_SECRET` | урт санамсаргүй мөр — `openssl rand -base64 36` |
| `TZ` | `Asia/Ulaanbaatar` |
| `TUNNEL_TOKEN` | Cloudflare Tunnel-ийн токен (интернэтээр гаргах бол) |

### 3. Ажиллуулах

```bash
./deploy.sh
```

Энэ нь тест ажлуулж, image барьж, prod + tunnel профайлыг хамт өргөөд,
дотоод хуудас, дотоод API, гадаад хаяг гурвыг шалгана. Зөвхөн frontend
өөрчилсөн бол `./deploy.sh --frontend` хурдан.

Дууссаны дараа `http://localhost` (эсвэл дотоод сүлжээнээс машины IP),
tunnel тохируулсан бол `https://pos.таны-домэйн` дээр нээгдэнэ.

### 4. Цахилгаан тасарсны дараа өөрөө асахаар тохируулах — ЗААВАЛ

Станцын машин цахилгаан унтарсны дараа хүн оролцоогүйгээр сэргэх ёстой.

**Docker өөрөө асна:**

```bash
sudo systemctl enable docker
```

Контейнерууд `restart: unless-stopped` тул Docker асмагц өөрсдөө босно —
`cloudflared` мөн адил, өөрөөр хэлбэл интернэтийн хаяг ч сэргэнэ.

**Ubuntu Desktop-ын унтах горимыг хаах.** Энэ бол хамгийн түгээмэл
алдаа: Ubuntu Desktop цонхоо түгжсэний дараа машиныг унтууруулдаг тул
түгээгч утаснаасаа хандахад систем "унтарсан" байдаг.

```bash
sudo systemctl mask sleep.target suspend.target hibernate.target hybrid-sleep.target
```

Settings → Power дотор **Automatic Suspend: Off**, **Screen Blank: Never**
болгоно. Дэлгэц унтарсан ч машин ажиллаж байх ёстой.

**Автоматаар нэвтрэх** (сервер шиг ашиглах бол): Settings → Users →
Automatic Login: On. Ингэснээр цахилгаан ирмэгц хүн ПИН оруулахгүйгээр
систем бүрэн босно.

### 5. Windows машинаас өгөгдлөө зөөх

Хуучин машин дээр (PowerShell):

```powershell
.\backup-data.bat
```

`kolonk.dump` (+ байвал `kolonk-uploads.zip`) файлыг USB-ээр зөөнө.
Ubuntu дээр:


> Windows-оос ирсэн `.zip`-ийг задлаад дахин `tar czf` хийх, эсвэл зургаа
> алдахгүй бол алгасаж болно.

### Ubuntu дээрх түгээмэл алдаа

| Алдаа | Шалтгаан → Шийдэл |
|---|---|
| `permission denied while trying to connect to the Docker daemon socket` | `docker` бүлэгт ороогүй эсвэл дахин нэвтрээгүй. → `sudo usermod -aG docker $USER`, дараа нь **гарч дахин нэвтэрнэ** |
| `bash: ./deploy.sh: Permission denied` | Ажиллах эрх алга. → `chmod +x deploy.sh` |
| `bash: ./deploy.sh: /usr/bin/env: bad interpreter` | Файл CRLF мөрийн төгсгөлтэй clone хийгдсэн. → `sed -i 's/\r$//' *.sh` |
| Порт 80 завгүй (`address already in use`) | Ubuntu дээр Apache/nginx урьдчилж суусан байна. → `sudo systemctl disable --now apache2 nginx` |
| Түгээгч утаснаасаа хандахад "холбогдохгүй" | Машин унтсан байна. → Дээрх 4-р алхмын `systemctl mask sleep.target ...` |


### Гар утаснаас (Android / iPhone) хандах

Түгээгчид гар утаснаасаа ашиглах бол утас, компьютер хоёр **нэг Wi-Fi сүлжээнд**
байхад хангалттай:

1. Компьютер дээрээ IP-гээ олно: терминалд `ipconfig` → *Wireless LAN adapter*
   → **IPv4 Address** (жишээ нь `192.168.1.31`).
2. Утасны browser-т (Chrome/Safari) `http://192.168.1.31` гэж нээнэ — систем
   POS-ынхоо нэвтрэх дэлгэцийг шууд харуулна.

Холбогдохгүй бол дараах дарааллаар шалгана:

- **Windows-ийн сүлжээний төрөл**: Settings → Network & internet → Wi-Fi →
  сүлжээнийхээ нэр → Network profile type → **Private** болгоно.
- **Router-ын AP/Client isolation** идэвхтэй бол унтраана (зочны Wi-Fi ихэвчлэн
  төхөөрөмж хооронд хориглодог).
- Firewall дүрэм гараар нэмэх (админ PowerShell):

  ```powershell
  netsh advfirewall firewall add rule name="Kolonk HTTP 80" dir=in action=allow protocol=TCP localport=80
  ```

> Байнгын ашиглалтад router дээрээ энэ компьютерт **тогтмол IP** (DHCP
> reservation) оноож өгвөл хаяг өөрчлөгдөхгүй.

### Интернэтээр хандах (mobile data) — Cloudflare Tunnel

Wi-Fi биш, **гар утасны дата**-гаар ажиллуулах бол систем интернэтэд гарах ёстой.
Cloudflare Tunnel нь компьютерээс **гадагш** холбогддог тул роутер дээр порт нээх,
статик IP авах шаардлагагүй бөгөөд CGNAT-ын цаанаас ч ажиллана. HTTPS автоматаар
нэмэгдэнэ.

**1. Домэйн бэлдэх.** Cloudflare Access ашиглах бол өөрийн домэйн заавал хэрэгтэй
(түр `trycloudflare.com` хаяг дээр Access ажиллахгүй). Хямд сонголт: Porkbun,
Namecheap зэрэгт `.xyz` / `.top` эхний жилдээ ~3,000–10,000₮. Худалдаж авсны дараа
Cloudflare-т `Add a site` → nameserver-ээ Cloudflare руу заана.

**2. Tunnel үүсгэх.** [Cloudflare Zero Trust](https://one.dash.cloudflare.com) →
**Networks → Tunnels → Create a tunnel** → *Cloudflared* → нэр өгнө → орчин
сонгохдоо **Docker** дээр дарж гарч ирэх командаас **токеныг** хуулж авна
(`eyJ...` эхэлсэн урт мөр).

**3. Токенийг `.env`-д хийх:**

```
TUNNEL_TOKEN=eyJhIjoi...
```

**4. Нийтийн хаяг холбох.** Мөн тэр дэлгэц дээр **Public Hostname** нэмнэ:

| Талбар | Утга |
|---|---|
| Subdomain | `pos` |
| Domain | таны домэйн |
| Type | `HTTP` |
| URL | `nginx:80` |

> `nginx:80` гэж бичнэ — `localhost` биш. Хоёулаа нэг Docker сүлжээнд байгаа тул
> контейнерийн нэрээр шууд холбогдоно.

**5. Ажиллуулах:**

```bash
docker compose --profile prod --profile tunnel up -d
```

Хэдэн секундын дараа `https://pos.таны-домэйн` хаягаар дэлхийн хаанаас ч нээгдэнэ.
Холболтыг шалгах: `docker compose logs cloudflared` дотор
`Registered tunnel connection` мөр гарсан байна.

**6. Cloudflare Access тавих (заавал).** Zero Trust → **Access → Applications →
Add an application → Self-hosted** → дээрх хаягаа оруулна → *Policy* дээр
ажилтнуудынхаа имэйлийг жагсааж, аргад **One-time PIN** сонгоно. Ингэснээр
системд хүрэхээс өмнө имэйлийн баталгаажуулалт давах шаардлагатай болно.

> **Session Duration**-г сарын хугацаатай болгоорой. Үгүй бол түгээгч ажил бүрд
> имэйлээр код авах шаардлагатай болж, ажлын урсгал удаашрална.

**7. Ажиллуулахаас өмнө ПИН кодуудыг солих.** Демо бүртгэлүүд `000000` ПИН-тэй.
Интернэтэд гарахын өмнө ажилтан бүрийн ПИН-г солино (доорх *ПИН солих* хэсэг).

Систем нэвтрэлтийн оролдлогыг өөрөө хязгаарладаг: нэг ажилтан **5 удаа** буруу
бичвэл 15 минут түгжигдэнэ, нэг IP хаягаас **20 удаа** буруу бичвэл тэр хаяг
15 минут хаагдана. Гэхдээ энэ нь Access-ийг орлохгүй — хоёуланг нь хэрэглэнэ.

### ПИН солих

Дэлгэцээс: **Хэрэглэгч** хуудас → тухайн хэрэглэгч → **ПИН сэргээх** (зөвхөн Эзэн).

Эсвэл командаас (`backend` хавтаснаас):

```bash
python -m scripts.set_pin 000000            # бүх хэрэглэгчид
python -m scripts.set_pin 4821 dorj         # зөвхөн нэгд
```

> Бүх хэрэглэгч нэг ПИН-тэй байх нь зөвхөн туршилтад тохиромжтой. Аудит логоос
> хэн ямар үйлдэл хийснийг ялгах боломжгүй болох тул **ашиглалтад оруулахын
> өмнө** хүн бүрд өөр ПИН олгоно уу.

## Үндсэн урсгал

1. **Нэвтрэх** — хэрэглэгчийн плитка сонгоод ПИН оруулна.
2. **Ээлж нээх** — кассын мөнгө, савны хэмжилт (дип), насосны тоолуурын заалт.
3. **Түлш зарах** — насос сонгох → бэлэн хэмжээ (10/20/30л, дүүргэх) → таталт → төлбөр.
4. **Бараа зарах** — хайлт/ангилал → сагс → төлбөр (хуваасан төлбөр дэмжинэ).
   Талбайн **Грам бүтээгдэхүүн** плиткаас задлан зарах тос, шингэнийг яг түлш
   шиг литр/дүнгээр борлуулна. Ширхэг барааг задлахдаа тэндээс «Задлах».
5. **Ээлж хаах** — кассын тоолол, савны дип, тоолуур → зөрүү автоматаар бодогдож,
   НББ-д бичигдэнэ (кассын дутагдал/илүүдэл, шатахууны хорогдол).
6. **Эзний хяналт** — үнийн өөрчлөлт, буцаалт батлах, санхүүгийн тайлан.

## Нягтлан бодох бүртгэл

Давхар бичилт (double-entry). Бизнес үйл явдал бүр автоматаар журналд бичигдэнэ.
Идемпотент: `(source_type, source_id, event_type)` давхардахгүй.

Санхүүгийн тайлан: Шалгах баланс · Орлого зардлын тайлан (түлшний төрлөөр бохир ашиг) ·
Баланс · Мөнгөн урсгал · Нөөцийн үнэлгээ (Moving Average).

Бүрэн бүтэн байдлын шалгалт: `GET /api/accounting/integrity`.

### Тайлангийн төв

**Цэс: Санхүү → Тайлан.** Эхлээд **тайлангийн төрөл** сонгоно:

| Тайлан | Агуулга |
|---|---|
| Гүйлгээний тайлан | Бүх төрлийн гүйлгээг сонгосон бүлэглэлээр |
| Бараа материалын тайлан /өртгөөр/ | Эхний үлдэгдэл → орлого → зарлага → эцсийн үлдэгдэл |
| Борлуулалтын тайлан | Зөвхөн борлуулалт — ажилтан, түлш, ангиллаар |
| Зардлын тайлан | Үйл ажиллагааны зардал дансаар |

Шүүлт бүр **олон утга** авна (данс, салбар, түлш, ангилал, ажилтан,
гүйлгээний төрөл). **Юу ч сонгоогүй бол "Бүгд"** — тайлан бүр дээр ижил.

- **Гүйлгээний төрөл**: Борлуулалт · Орлого · Зарлага · Буцаалт · Залруулга
- **Бүлэглэл**: Данс · Салбар · Ажилтан · Түлш · Барааны ангилал · Бараа ·
  Гүйлгээний төрөл · Өдрөөр — олныг дараалуулж шаталсан тайлан гаргана
- **Огноо**: `YYYY-MM-DD` гараар бичих эсвэл хуанлийн товчоор сонгоно

**Задаргаа — хоёр түвшний давхар товшилт:**

1. Тайлангийн **аль ч мөр дээр давхар товшиход** тухайн бүлгийн бүх гүйлгээ
   тэр дороо дэлгэгдэнэ (`▸` → `▾`). Дахин товшвол хаагдана. Дээд түвшний мөр
   дээр товшвол дэд бүлгүүдийн бүх гүйлгээ орно.
2. **Задаргааны мөр дээр давхар товшиход** тухайн гүйлгээ бүрэн нээгдэнэ:

- *Борлуулалт* — юу юу авсан, хэн зарсан, хэзээ, төлбөрийн хэлбэр, авсан мөнгө
  ба хариулт, НӨАТ, нийт дүн
- *Орлого* — нийлүүлэгч, баримтын дугаар, барааны мөрүүд, тээврийн зардал,
  нэгж өртөг (тээвэртэй)
- *Зардал* — данс, төлбөрийн хэлбэр, тайлбар
- *Залруулга* — сав, литр, дараах үлдэгдэл

Тайлан бүр **Хэвлэх** ба **Excel татах** боломжтой.

### Салбар

**Цэс: Удирдлага → Салбар** (зөвхөн эзэн үүсгэж, засна).

| Дүр | Салбар | Юу харах вэ |
|---|---|---|
| Түгээгч | харьяалагдана (заавал) | зөвхөн өөрийн салбар |
| Менежер | харьяалагдахгүй | **бүх салбар** |
| Эзэн | харьяалагдахгүй | **бүх салбар** + салбар үүсгэх |

- **Түгээгч нэмэхэд салбар заавал сонгоно** — эс бөгөөс систем татгалзана.
  Менежер, эзэнд салбарын талбар харагдахгүй (бүгдийг хардаг).
- **Түгээгч нэвтрэхэд салбар нь автоматаар сонгогдож**, толгойд нэр нь
  харагдана. Ээлж нээх, борлуулалт бүр тэр салбарт бичигдэнэ.
- Менежер, эзний толгойд "Бүх салбар" гэж харагдана.
- Ажилтантай эсвэл нээлттэй ээлжтэй салбарыг идэвхгүй болгохыг систем хориглоно.

`branches` хүснэгттэй — сав, насос, ээлж, борлуулалт, ажилтан, зардал,
хэрэглэгч бүгд салбартай холбогдсон. Тайлангийн **Салбар** шүүлт, бүлэглэл
шинэ салбар нэмэхэд ямар ч кодын өөрчлөлтгүйгээр өргөжинө.

### Түгээгчийн өдрийн ээлж (ПОС-гүй горим)

**Тохиргоо → «ПОС борлуулалт ашиглах»-ыг унтраавал** идэвхжинэ. Касс/Дэлгүүр
цэс нуугдаж, Ээлж хуудас түгээгчийн горимд шилжинэ:

1. **Нээлт** — эхний бэлэн мөнгө + насос бүрийн **миль** (тоолуурын заалт),
   зурагтай. Савны хэмжилт шаардахгүй.
2. **Үнэ өдрийн дундуур өөрчлөгдвөл** — «Үнэ өөрчлөгдсөн» товчоор хошуу
   бүрд шинэ үнэ аль мильд эхэлснийг зурагтай тэмдэглэнэ. Хаалтын тооцоо
   сегментчилж бодно (өмнөх литр хуучин үнээр, дараах нь шинээр).
3. **Өдрийн хаалт** — 8 алхамт цонх: эцсийн миль (зурагтай) → бэлэн мөнгө →
   settlement (НӨАТ-тэй/гүй, зурагтай) → тос/барааны борлуулалт → зээлийн
   борлуулалт (гэрээт харилцагч, литр/дүнгээр + бараа) → өглөг төлөлт
   (бэлэн/карт/шилжүүлэг) → зарлага → **тулгалт**.
4. Хаалт бүх баримтыг нэг гүйлгээнд үүсгэнэ: зээл нь гэрээт борлуулалт,
   тос нь бэлэн борлуулалт, үлдсэн түлш нь миль×үнэ сегментээр нэгдсэн
   борлуулалт (settlement нь карт, үлдэгдэл бэлэн). Кассын зөрүү автоматаар
   журналд бичигдэнэ — нягтлан тайлангаас «Өдрийн тулгалт» хэсгийг шалгана.

Тосны үнийн өөрчлөлтийг **маргаашнаас** эхлүүлье гэвэл үнийн өөрчлөлтийн
хүсэлтэд «Хэрэгжих огноо» сонго — батлагдсан ч тэр өдрийг хүртэл хуучин
үнэ үйлчилж, worker шөнө дунд шинэ үнийг тавина.

### Банкны хуулга

**Цэс: Санхүү → Харилцах данс / Банкны хуулга.**

1. **Харилцах данс** — банк, дансны дугаар, эзэмшигч, эхний үлдэгдэл. Хуулга
   оруулахад дансны дугаараар нь автоматаар холбогдоно. Нэг дансыг «шимтгэлийн
   анхдагч» болгож тэмдэглэнэ.
2. **Хуулга оруулах** — банкнаас татсан Excel (`Statement_MNT_5301234567.xlsx`).
   Багана солигдсон ч динамикаар танина; `SETTLEMENT` бүхий мөрийг ПОС-ын
   тооцоо, «хураамж/шимтгэл» бүхий мөрийг банкны шимтгэл гэж ялгана.
3. **Тохиргоо** — ПОС орлого аль гэрээт харилцагчийн төлбөр болох, шимтгэл
   ямар зардлын ангилалд орох. Оруулах үед тэдгээр мөр урьдчилж бөглөгдөнө.
4. **Бүртгэх** — орлого нь харилцагчийн авлагыг хааж, зарлага нь зардал болно.
   Шимтгэлийг мөр бүрээр нь биш, **нийлбэрээр нь нэг зардал** болгож хаана.
5. **Буцаах** — үүссэн төлбөр/зардал болон журналын бичилтийг хамт устгаж
   нөлөөг бүрэн сэргээнэ (аудит логт үлдэнэ).

Дансны үлдэгдлийг ерөнхий дэвтрээс гаргадаг тул `Σ(данс) + хуваарилаагүй` нь
`1110 Банк` дансны үлдэгдэлтэй үргэлж таарна.

### Бараа материалын тайлан /өртгөөр/

**Цэс: Санхүү → Бараа материалын тайлан.** Erkhet маягийн хөдөлгөөний тайлан:
**эхний үлдэгдэл → орлого → зарлага → эцсийн үлдэгдэл** (тоо ба дүн) + нэгж өртөг.

Задлан хөрвүүлэлт (ширхэг → грам) энд **Задлалт (гарсан)** / **Задлалт (орсон)**
гэсэн хос мөрөөр харагдана. Өртөг бүрэн шилждэг тул 1302 дансны дүн хөдлөхгүй.

"Тайлан авах" цонхны шүүлт:

| Талбар | Утга |
|---|---|
| Данс | 1301 Түлш · 1302 Бараа · Бүгд |
| Байршил | сав тус бүр (түлш) |
| Түлш | АИ-92 · АИ-95 · Дизель |
| Барааны ангилал | каталогийн ангиллууд |
| Бүлэглэл | Данс-Байршил · Данс-Бараа · Байршил-Бараа · Бараа |
| Гүйлгээний төрөл | Бүгд · Зөвхөн орлого · Зөвхөн зарлага |
| Эхний/эцсийн огноо | хугацааны муж |
| Гүйлгээний утга | тэмдэглэлээр хайх |
| Гүйлгээний задаргаа | гүйлгээ бүрийг үлдэгдэлтэй нь харуулах |
| Хоосон мөр алгасахгүй | хөдөлгөөнгүй мөрийг ч харуулах |

Жишээ — *1-р савны зөвхөн АИ-92, бүх төрлийн гүйлгээ, задаргаатай*: Байршил
`1-р сав`, Түлш `AI92`, Гүйлгээний төрөл `Бүгд`, огнооны муж, "Гүйлгээний
задаргаа харуулах" ✓.

Тайлан **Хэвлэх** (A4, толгой хуудас бүрд давтагдана) болон **Excel татах**
боломжтой. Гарсан тайлан нь ерөнхий дэвтрийн `1301 + 1302` дансны үлдэгдэлтэй
**яг тэнцэнэ** — үүнийг end-to-end шалгалт автоматаар шалгадаг.

### Үйл ажиллагааны зардал

**Цэс: Санхүү → Зардал** (менежер, эзэн). Цалин, цахилгаан, түрээс, засвар зэрэг
борлуулалттай холбоогүй зардлыг эндээс бүртгэнэ — үүнгүйгээр орлого зардлын
тайлан зөвхөн **бохир** ашиг харуулна.

- 15 зардлын данс (5301–5901): цалин, НД шимтгэл, цахилгаан, ус/дулаан, холбоо,
  түрээс, засвар, тээвэр, бичиг хэрэг, сурталчилгаа, банкны шимтгэл, татвар,
  хамгаалалт, элэгдэл, бусад.
- Төлбөрийн 3 хэлбэр: **кассаас бэлнээр** · **харилцахаас** · **нийлүүлэгчийн
  өглөгөөр** (сүүлийнх нь AP нэхэмжлэх автоматаар үүсгэнэ).
- Дүнг **төлсөн нийт дүнгээр** оруулна; "Дүнд НӨАТ шингэсэн" сонговол орох НӨАТ
  автоматаар салгаж 1402 дансанд бичнэ.
- Бэлнээр төлсөн зардал **ээлжийн байвал зохих кассаас автоматаар хасагдана**.
- Борлуулалтын өртөг (5101/5102) болон зөрүүний данс (5201/5902) руу гараар
  зардал бичихийг систем хориглоно — тэдгээр нь автоматаар л бичигддэг.

Цэвэр ашиг Эзний хяналтын самбар дээр тусдаа плиткаар харагдана.

### Цалингийн тооцоо

**Цэс: Санхүү → Цалин / Ажилтан** (менежер тооцоолно, **эзэн батлаж олгоно**).

Урсгал: сар сонгож **Тооцоолох** → мөр дээр дарж ажилласан хоног, урамшуулал,
урьдчилгаа засах → **Цалин батлах** (ерөнхий дэвтэрт бичигдэж, засах боломжгүй
болно) → цалин, ХХОАТ, НДШ-ийн өглөгийг тус тусад нь **Төлөх**.

Ажилтан тус бүрд:

```
ажилласан цалин = үндсэн цалин × ажилласан хоног / сарын хоног
нийт цалин      = ажилласан цалин + урамшуулал
НДШ (ажилтан)   = нийт цалин × 11.5%
ХХОАТ           = (нийт цалин − НДШ) × 10% − 20,000₮ хөнгөлөлт
гарт олгох      = нийт цалин − НДШ − ХХОАТ − урьдчилгаа
```

**Сарын хоног** нь календарийн жинхэнэ хоног — 2 сар 28 (өндөр жилд 29),
4 сар 30, 7 сар 31. Хувь тэнцүүлэх тооцоо үүнийг ашиглана.

**Сарын дундуур ажилд орсон/гарсан** ажилтны цалин автоматаар хуваарилагдана.
Ажилтны хуудсанд **ажилд орсон** ба **ажлаас гарсан** огноог бөглөнө:

| Тохиолдол | 7-р сар (31 хоног) | Тооцоо |
|---|---|---|
| 07-15-нд ажилд орсон | 17 хоног (07-15 … 07-31) | 3,100,000 × 17/31 = **1,700,000₮** |
| 08-20-нд ажлаас гарсан | 8-р сард 20 хоног | 8-р сарын цалин 20/31 |
| Ажилд орохоос өмнөх сар | — | жагсаалтад **орохгүй** |
| Ажлаас гарсны дараах сар | — | жагсаалтад **орохгүй** |

Хэсэгчилсэн сар шар өнгөөр онцлогдож, хугацааг нь хажууд нь харуулна:
`Гарсан Тест · 17/31 хоног (2026.07.15–2026.07.31)`.

Ажлаас гарсан хүн идэвхгүй болсон ч **сүүлийн сарын цалингаа авна**.

Тооцоо хийсний дараа шинэ ажилтан нэмсэн бол **Дахин тооцоолох** дарахад
жагсаалт ажилтны бүртгэлтэй дахин таарна (шинэ хүн нэмэгдэж, тухайн сард
ажиллаагүй болсон хүн хасагдана). Батлагдсан цалин өөрчлөгдөхгүй.

**Урьдчилгаа:** Ажилтан хуудаснаас "Урьдчилгаа олгох" — авлага болж бүртгэгдэж,
цалин бодох үед автоматаар суутгагдана. Бэлнээр олгосон бол ээлжийн кассаас
автоматаар хасагдана.

> **Хувь хэмжээг нягтлантайгаа тулгана уу.** НДШ (ажилтан 11.5%, ажил олгогч
> 12.5%), ХХОАТ 10%, сарын хөнгөлөлт 20,000₮ гэсэн **анхдагч** утгатай ирнэ.
> Эдгээр нь **Тохиргоо** хуудсанд байгаа тул хууль өөрчлөгдөхөд програм засах
> шаардлагагүй. Тухайн сарын хувь хэмжээ тооцоолох үедээ хадгалагдана —
> дараа тохиргоо солигдсон ч хуучин сарын тооцоо хэвээр үлдэнэ.
